# 提示词工程指南

## 概述

提示词工程(Prompt Engineering)是一门与AI模型高效交互的艺术和科学。掌握提示词工程技巧可以显著提升AI工具的输出质量。

## 基本原则

### 1. 清晰明确

**原则**: 避免歧义，表达清晰

**不好的示例**:
```
写一个函数
```

**好的示例**:
```
用Python编写一个函数，接收整数列表，返回列表中的最大值和最小值
```

### 2. 提供上下文

**原则**: 给予足够的背景信息

**不好的示例**:
```
这段代码有问题吗？
[代码]
```

**好的示例**:
```
以下是一个用户认证的中间件函数，应该验证JWT token。
但在生产环境中出现了认证失败的问题。
运行环境：Node.js 18, Express 4.x, jsonwebtoken 9.x
请检查是否有问题：
[代码]
```

### 3. 分步骤引导

**原则**: 将复杂任务分解为多个步骤

**示例**:
```
请帮我设计一个用户注册功能，按以下步骤：
1. 首先，设计数据库表结构
2. 然后，实现注册API接口
3. 接着，添加邮箱验证功能
4. 最后，编写单元测试
```

### 4. 指定格式

**原则**: 明确期望的输出格式

**示例**:
```
请分析这段代码的时间复杂度，按以下格式回答：
- 最好情况：O(?)
- 平均情况：O(?)
- 最坏情况：O(?)
- 分析说明：[详细说明]
```

## 高级技巧

### 1. Few-Shot Learning (少样本学习)

提供几个示例，让AI理解你的需求模式

**示例**:
```
请将以下函数名转换为驼峰命名法，示例：

输入：get_user_name
输出：getUserName

输入：calculate_total_price
输出：calculateTotalPrice

现在请转换：
- fetch_data_from_api
- validate_email_address
- send_notification_email
```

### 2. Chain-of-Thought (思维链)

要求AI展示推理过程

**示例**:
```
请分析这段代码的性能问题，展示你的思考过程：
1. 首先识别潜在的性能瓶颈
2. 分析每个瓶颈的影响程度
3. 提出具体的优化方案
4. 评估优化后的预期改进

[代码]
```

### 3. Role Playing (角色扮演)

为AI分配特定角色

**示例**:
```
你是一位有15年经验的数据库架构师，擅长MySQL和PostgreSQL。
请从数据库专家的角度，审查以下查询语句的性能问题：
[SQL语句]
```

### 4. Constraint Setting (约束设定)

明确限制条件

**示例**:
```
请实现一个排序算法，约束条件：
- 空间复杂度必须是O(1)（原地排序）
- 必须是稳定排序
- 不使用递归
- 代码行数不超过30行
```

### 5. Template Filling (模板填充)

提供结构化的模板

**示例**:
```
请按以下模板分析这个设计模式：

模式名称：[?]
问题场景：[?]
解决方案：[?]
适用场景：[?]
优点：[?]
缺点：[?]
代码示例：[?]

设计模式：[具体的设计模式]
```

## 针对不同任务的提示词策略

### 1. 代码生成

**结构化提示词**:
```
任务：[具体任务]
语言/框架：[技术栈]
输入：[输入参数]
输出：[期望输出]
约束：[限制条件]
要求：
- [要求1]
- [要求2]
- [要求3]
```

### 2. 代码审查

**审查清单**:
```
请审查以下代码，检查：
1. 代码规范
   - 命名是否清晰
   - 格式是否统一
2. 逻辑正确性
   - 边界条件处理
   - 错误处理
3. 性能
   - 时间复杂度
   - 空间复杂度
4. 安全性
   - 输入验证
   - 潜在漏洞

[代码]
```

### 3. Bug修复

**问题描述框架**:
```
问题描述：[简要描述]
期望行为：[应该怎样]
实际行为：[实际怎样]
错误信息：[错误日志]
复现步骤：
1. [步骤1]
2. [步骤2]
3. [步骤3]
环境信息：[操作系统、版本等]
相关代码：[代码片段]
```

### 4. 架构设计

**需求分析框架**:
```
请设计[系统名称]的架构，需求如下：

功能需求：
- [需求1]
- [需求2]

非功能需求：
- 性能：[指标]
- 可用性：[指标]
- 扩展性：[要求]

技术约束：
- [约束1]
- [约束2]

请提供：
1. 整体架构图
2. 核心组件说明
3. 技术选型建议
4. 关键设计决策
```

### 5. 测试用例生成

**测试覆盖清单**:
```
请为以下函数生成测试用例：

[函数代码]

测试覆盖要求：
1. 正常场景
   - [场景1]
   - [场景2]
2. 边界条件
   - 空输入
   - 极大/极小值
3. 异常场景
   - 无效输入
   - 类型错误

使用[测试框架]编写
```

## 常见错误与改进

### 错误1: 提示词过于简单

❌ **不好**:
```
优化这段代码
```

✅ **改进**:
```
请优化以下代码的性能，重点关注：
1. 减少循环嵌套
2. 避免重复计算
3. 提高代码可读性

[代码]

请提供优化后的代码和改进说明
```

### 错误2: 缺少具体要求

❌ **不好**:
```
写一个API
```

✅ **改进**:
```
使用Flask编写一个RESTful API，要求：
- 端点：POST /api/users
- 功能：创建新用户
- 输入：JSON格式的用户信息(name, email, password)
- 输出：创建成功返回用户ID，失败返回错误信息
- 需要：邮箱格式验证、密码强度检查
```

### 错误3: 一次性要求太多

❌ **不好**:
```
请实现完整的电商系统，包括用户、商品、订单、支付、物流、评价等所有功能
```

✅ **改进**:
```
第一步：请先设计电商系统的整体架构和核心模块

[收到回复后]

第二步：请实现用户模块，包括注册、登录、个人信息管理
```

### 错误4: 上下文不足

❌ **不好**:
```
为什么报错？
```

✅ **改进**:
```
我在运行Python脚本时遇到以下错误：

错误信息：
TypeError: unsupported operand type(s) for +: 'int' and 'str'

代码：
[相关代码]

这个错误发生在第15行，我想将用户输入的数字累加，
请帮我分析原因并提供解决方案
```

## 提示词模板库

### 模板1: 功能实现

```
请用[语言]实现[功能]

需求说明：
- 功能描述：[详细描述]
- 输入：[输入说明]
- 输出：[输出说明]
- 边界条件：[特殊情况]

技术要求：
- [要求1]
- [要求2]

代码风格：
- [风格要求]
```

### 模板2: 代码重构

```
请重构以下代码：

[原始代码]

重构目标：
1. [目标1]
2. [目标2]
3. [目标3]

保持不变：
- 外部接口不变
- 功能行为一致

请提供重构后的代码和改进说明
```

### 模板3: 问题诊断

```
问题：[问题简述]

详细情况：
- 发生时间：[时间]
- 频率：[频率]
- 影响范围：[范围]

环境信息：
- 系统：[系统信息]
- 版本：[版本信息]
- 依赖：[依赖库]

错误日志：
[日志内容]

已尝试的解决方案：
1. [方案1] - [结果]
2. [方案2] - [结果]

请帮我分析根本原因并提供解决方案
```

### 模板4: 学习理解

```
请解释[概念/技术]

希望了解：
1. 基本定义和原理
2. 为什么需要它？解决什么问题？
3. 如何使用？（附带代码示例）
4. 最佳实践和常见陷阱
5. 与[相关技术]的区别

我的背景：[你的技术背景]
```

## 效果评估

好的提示词应该产生：
- ✅ 准确的答案
- ✅ 完整的信息
- ✅ 可执行的代码
- ✅ 清晰的解释
- ✅ 相关的示例

如果输出不理想，尝试：
1. 增加更多上下文
2. 提供示例
3. 分解问题
4. 明确约束条件
5. 指定输出格式
